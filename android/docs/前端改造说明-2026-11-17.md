## 2 当前产品行为（按契约）

### 2.1 页面与主链

登录/注册 → 身份资料（可跳过）→ 首页三类通知 → 详情（关注/取消关注）→ 我的关注；「我的」含身份摘要、偏好设置、环境切换、退出。

- 首页只有三个 Tab：**科研、竞赛与创新** / **奖助与学生权益** / **日常通知**；`unknown` 只作为"类别待确认"容器，不加第四 Tab。
- 不显示任何综合分/加权/重要性；顺序完全按后端返回，前端不本机重排、不先分页再筛选。
- 列表项：标题右侧摘要显示**最需要关注的一个日期 + 最多两条收益**，下方标签行显示其余日期、面向群体、文件状态与状态角标；同一日期/收益只出现一次（`NoticeCardLogic`，有单测）。日期标签按 报名/办理、事项举行、政策有效期 分组，窄屏换行。
- 详情：标题/来源/发布时间 → **顶部全部标签**（日期、收益、面向群体、文件状态；`NoticeLabelTags`）→ 标签外的时间补充说明（未核实窗口原因、未被标签引用的窗口；`DetailExtras`）→ 正文（纯文本，保留完整/部分/仅标题/未取得）→ 不确定性 → 折叠的「来源与附件 / 政策依据 / 数据说明」（默认收起，标题带摘要，`ExpandableSection`）。**不再重复渲染关键日期/收益/面向群体/文件状态区块。** 不调用 explanation/四问/摘要/提醒/忽略接口。
- 动作只有「关注/取消关注」：提交目标状态（不是 toggle）+ `expected_version` + 幂等键；星标不等于报名完成。
- 我的关注：按服务端关注时间倒序（前端不重排）；过期/首页隐藏/撤销/旧正文仍保留，直到主动取消。
- 六态分开：加载 / 内容 / 空 / 离线缓存 / 错误 / 会话失效；网络失败不退出登录、不清草稿。

## 4 本轮做了什么（按层）

### 4.1 网络层（对齐真实契约，修掉三处后端已核对问题）

1. **版本放 JSON 正文**：`PATCH /v1/me/profile`、`PATCH /v1/me/preferences` 的 `expected_version` 在正文（`Long`），不再依赖 `X-Expected-Version` 头（只发头会 422）。写请求统一带 8—128 字符 `Idempotency-Key`（UUID）。
2. **资料响应外层结构**：`GET/PATCH /v1/me/profile` 按 `{completed, profile, version}` 解析；`profile` 可为 null；`major_group` 可为 null。
3. **学校选择控件**：加载期间禁用、加载完成后可选（旧代码把 `loading` 直接传 `enabled`）。
4. 年级目录 `items[].value` 是**整数 1—8**；目录响应 `message` 可为 null 或说明文字（如课程目录待核验）——都会展示。
5. 补 `POST /v1/auth/refresh`（不续期）；`POST /v1/auth/logout` 发空正文、不解 204 JSON；注册/登录成功用 `SessionView{user,expires_at(Unix 秒),csrf_token}`。
6. 错误码分类覆盖真实后端会返回的全部错误：400 `request_rejected`、401 `invalid_credentials`/`session_invalid`、403 `csrf_invalid`/`origin_forbidden`、404 `school_not_supported`/`college_not_available`/`notice_not_found`/`request_rejected`、409 `email_in_use`/`version_conflict`/`key_payload_conflict`/`feed_changed`、413/415、422 `validation_error`（带 `details[].field`）/`major_not_available`、429、500/503、planned 404。
7. **认证世代保护（S1-A08）**：`AuthGeneration` + 线程局部 `RequestGeneration` + `GenerationAwareCookieJar`。登录/退出推进世代；旧世代请求的 Set-Cookie、Cookie 读取与页面结果都被丢弃。A 退出后 B 登录，A 迟到的删除 Cookie/401/旧登录响应不会污染 B。
8. 环境/地址/账号隔离的 Cookie、CSRF、缓存键（见 `CacheKey` 与 `Env.storageNamespaceOf`）。

**联调实测的契约细节（后端值，必须知道）**：

- 错误 `message` 文案不固定、与 OpenAPI 示例可能不同；**只能按 `error.code` 分支，禁止依赖 message**。
- 422 `details[].field` 带 `body.`/`header.`/`query.` 前缀（如 `body.expected_version`、`header.Idempotency-Key`）；页面已做前缀归一化后再匹配字段。
- 只发 `X-Expected-Version` 头会 422（`body.expected_version` missing）；该头实际未实现，版本必须放 JSON 正文整数（字符串 `"2"` 会 422 `int_type`）。
- `GET /v1/catalog/grades` 没有 `message` 字段（其他目录有 `{items,message}`），`items[].value` 是 JSON 整数。
- 资料 `version` 外层与 `profile` 内各一份且相等；偏好只有外层 `version`；`major_group` 当前恒为 null。
- 提前拒绝（403 `origin_forbidden` / 413 / 415）可能没有 `X-Request-ID` 响应头，但正文有 `request_id`，客户端以正文为准。
- planned `/v2/*` 返回 **404 `request_rejected`**；运行服务的旧 v1 通知/来源/采集路由不属于 app-v2 契约，不要接。
- 限流：同一邮箱按动作 10 次/15 分钟（第 11 次 429，成功也计数）、IP 60 次/15 分钟；频繁联调需退避。
- dev 模式（`serve --dev`）Cookie 无 `Secure`（HttpOnly/SameSite=Lax/Path=/、30 天）；原生无 Origin 请求不受 CORS 影响。

### 4.2 数据层

- `ProfileResponse` / `Profile` / `ProfileEdit`（入学年份三态：省略 / null 清除 / 整数）；`Preferences`（四组 + 独立 `Long` 版本）。
- 通知：`NoticeItem/NoticeDetail` 对齐目标契约（`date_labels[].group`、`benefits{items,priority_tier,confirmation,policy_version}`、`audience_labels`、`status_labels`、`lifecycle`、`follow`、`evaluation_context`、`body_status`、`access_reason`、`processing`、`uncertainties`；详情另含 `body/segments/sources/attachments/evidence_refs/policy_references`）。
- `FollowStore`：所有来源（列表/详情/关注页/PUT/缓存）的 `FollowState` 按 version 合并，低版本不覆盖高版本。
- v2 五个 planned 操作：`ContractStatus` 是唯一开关（当前全 false）。为 false 时真实仓库直接返回 `ApiError.ContractPending(阶段, 功能)`，页面显示"接口尚未上线"，**不会发请求、不会回退样例**；backend 改为 implemented 后把对应常量改 true 并用真实响应跑解析测试即可接通。
- 缓存：列表 offset=0 成功写原始 JSON + 同步时间 + list_revision；详情按 noticeId 缓存；失败且可重试时读缓存并标注时间；关注页同样缓存。
- MOCK：`MockScenario` 读取 `assets/mock/scenario.json`，8 条合成通知（科研四档收益 + 待确认收益；奖助公示含申诉窗口；日常含"期限未注明"/"时间待确认"/仅标题/有更新），关注状态在内存中按契约版本递增。

## 5 必须遵守的工程红线

1. **契约优先**：字段/枚举/错误码以 `docs/contracts/app-v2/` 为准；发现不一致先记录、先与后端同步，再改。
2. **不得伪造数据**：未知就是 `UNKNOWN`/`null`；真实请求失败不得回退 MOCK 或旧 v1 通知接口；MOCK 必须常显"样例数据"。
3. **版本与幂等**：`expected_version` 放正文且用 `Long`；同一次逻辑保存的重试必须复用同一个 `Idempotency-Key`；正文一变就换新 key；409 要重读而不是自动覆盖。
4. **会话失效判定唯一**：只有 401 `session_invalid` 才需要重新登录；`invalid_credentials` 是登录错误；500/503/网络失败不清会话、不丢草稿。
5. **关注写目标状态**：`PUT` 提交 `starred: true/false`，绝不发 toggle；所有来源的 follow 按 version 合并。
6. **不调用未实现接口**：不加回 explanation / 四问 / materials / ignored / reminder / scope/explore；不要打开 `ContractStatus` 的开关，除非后端已交付真实响应。
7. **页面不重算业务**：不解析日期标签文本、不计算截止/倒计时/优先级、不本机排序分页、不显示综合分。
8. **每次改动补测试并提交**：`gradlew.bat testDebugUnitTest assembleDebug` 通过后再提交；不要在 `build/` 或 `local.properties` 里留改动。
